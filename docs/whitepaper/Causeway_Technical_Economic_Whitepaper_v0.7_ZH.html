01 / 执行摘要

执行摘要

Causeway 是面向预测市场的 AI 交易智能与可验证推理层。它把 Polymarket 的真实市场数据、AI 推理、风险预览、订单预览、Arc proof 和 Signal Track Record 组织成一个可审查工作流。

v0.7 的重点是把长期愿景从单一 AI 判断升级为 Causeway 自己的群体智能预测引擎：系统构建平行市场世界，组织多角色智能体推演事件传播路径，并把结果映射为可交易、可验证、可复盘的市场智能对象。

02 / 市场背景：预测市场进入概率基础设施阶段

市场背景：预测市场进入概率基础设施阶段

预测市场正在从事件下注界面演化为面向政治、宏观、体育、公司事件和链上活动的概率数据层。价格不只是交易结果，也是一种实时集成分散信息的公共信号。

市场扩大后，用户面对的不再是找不到市场，而是无法判断哪些市场已经反映信息、哪些相关市场存在滞后、哪些信号只是流动性噪声。

03 / 核心问题：为什么现有预测市场仍缺少智能层

核心问题：为什么现有预测市场仍缺少智能层

市场本质上是网络，界面却仍以列表呈现；AI 可以解释文本，却常常缺少可验证输入快照、推理轨迹、订单预览和事后绩效记录。

Causeway 要解决的是从事件到市场网络、从概率到 edge、从推理到用户确认、从事前记录到事后复盘的整条链路。

04 / 学术基础与价值计算框架

学术基础与价值计算框架

预测市场文献表明，二元合约价格在理想条件下可以近似解释为事件概率，但现实市场存在价差、手续费、滑点、限额、来源风险和结算歧义。Causeway 因此区分研究概率和可执行概率。

价值不来自“AI 觉得更可能”，而来自扣除交易摩擦、来源不确定性、规则风险和组合相关性之后仍然为正的 edgeNet。

p_mid = (bestBid + bestAsk) / 2p_exec_yes = ask_yes, p_exec_no = ask_noq_ai = calibratedForecast(event | marketSnapshot, sourceObjects, reasoningTrace)rawEdge_mid = q_ai - p_mid

区分中间价与可执行价格，避免高估市场 edge。

EV_token_yes = q_ai * 1 + (1 - q_ai) * 0 - ask_yes - cost_per_tokenROI_yes = EV_token_yes / ask_yesedgeNet = q_ai - ask_yes - feeRate - slippageBps - ruleRiskHaircut - sourceRiskHaircutBUY only if edgeNet > minEdge, depthAtLimit > targetSize, timeToClose > minWindow

只有扣除成本、滑点、规则风险和来源风险后仍为正的 edgeNet 才可能进入交易预览。

q_adj = clamp(0.5 + confidence * (q_ai - 0.5), 0.01, 0.99)b = (1 - p_exec) / p_execkellyFull = (b * q_adj - (1 - q_adj)) / b = (q_adj - p_exec) / (1 - p_exec)sizeUsd = bankroll * min(max(0, lambda * kellyFull), capMarket, capPortfolio, capCorrelation)

保守 Kelly 将模型概率向 50% 回缩，并受市场容量、组合相关性和预算约束。

Underround: Σ ask_i + fees + slippage < 1profitFloor_buyBasket = 1 - Σ ask_i - fees - slippage - settlementRiskIf event B implies event A, then P(B) ≤ P(A)semanticEdge = violation * relationConfidence * min(liquidityScore_A, liquidityScore_B)

互斥完备市场与语义蕴含关系用于发现价格不一致，但必须验证执行深度和规则一致性。

Brier_mean = mean((q_ai - y)^2)LogLoss_mean = mean(-[y * ln(q_ai + eps) + (1 - y) * ln(1 - q_ai + eps)])CalibrationError = Σ_k n_k / N * |mean(q_ai in bucket k) - mean(y in bucket k)|signalScore = z(edgeNet) + z(confidence) + z(liquidity) - z(spreadRisk) - z(sourceRisk) - z(correlationRisk)

长期评价不能只看 PnL，还要看校准、log loss、Brier score 和未执行机会表现。

05 / Causeway 的产品定义

Causeway 的产品定义

Causeway 是 Prediction-Market Trader Intelligence Layer。核心产物不是聊天回答，而是 market intelligence object：根市场、候选市场、语义关系、AI fair odds、market odds、edgeNet、风险解释、订单预览、Arc proof 和 track record。

默认边界是用户治理：AI 扩展论点、生成路径和风险预览；用户保留最终确认权和资金控制权。

06 / 我们已经解决了什么问题

我们已经解决了什么问题

系统已经将市场标题与真实可交易 outcome token 区分，建立 event、market、outcome、clobTokenId、价格、订单簿和流动性模型。

Arc proof 模块可以把 reasoning trace hash 锚定到 Arc；Arc USDC premium 可以通过 payment intent 和 Transfer log 验证会员权益。

07 / 系统架构与数据模型

系统架构与数据模型

架构包含 React 前端、NestJS/Prisma/PostgreSQL API、Polymarket Gamma/CLOB 数据、结构化 AI 输出、Arc proof 与 USDC 付款验证。

核心对象包括 Market Object、Inference Object、Causal Script、Order Intent、Arc Proof Capsule 和 Signal Track Record。

08 / AI Trader Intelligence：从概率到行动预览

AI Trader Intelligence：从概率到行动预览

成熟系统不应只输出 BUY，也要能输出 WATCH、VERIFY FIRST 或 AVOID。No Trade 是能力，因为它代表系统理解流动性、来源、规则和组合风险。

仓位建议来自 edgeNet、confidence、盘口深度、价差、预算、相关性和保守 Kelly，而不是固定下注金额。

09 / Arc Proof：可验证的 AI 推理记录

Arc Proof：可验证的 AI 推理记录

预测市场会用未来结果验证今天的判断，因此 AI 信号必须证明自己在结果发生前已经存在。Arc proof 把 reasoning trace 的 hash 写入链上，降低事后篡改空间。

Arc 不替代 Polymarket 交易链路，而是低成本、稳定币原生、EVM 兼容的审计层。

10 / Arc USDC Premium：会员订阅、可验证支付与智能体经济

Arc USDC Premium：会员订阅、可验证支付与智能体经济

当前会员订阅以 Arc USDC payment intent 解锁高级信号、完整推理轨迹、Arc proof 和更高额度分析能力。

未来 Causeway 可能使用基于 Arc 结算的 x402 调用，把订阅、按次报告、API、数据源和智能体能力购买统一到更细粒度的支付框架。

11 / x402 Agent Service Layer：未来智能体服务协议层

x402 Agent Service Layer：未来智能体服务协议层

x402 在 Causeway 中不是交易执行协议，而是 agent-to-service payment and access protocol。它适合数据源、验证服务、专业智能体、深度报告和 API 的按次访问与微支付。

Causeway 负责编排市场图谱、权限治理、风险控制和绩效追踪；x402 处理付费访问；Arc 记录 proof、payment record 和 reputation。

12 / Swarm Prediction Engine：从平行市场世界到预测万物

Swarm Prediction Engine：从平行市场世界到预测万物

Causeway 的长期目标不是让单一 AI 对一个市场给出一次性判断，而是构建面向预测市场的群体智能预测引擎。系统从真实事件出发，构建多个平行市场世界，让不同角色的智能体围绕证据、反例、概率、风险和执行边界进行推演。

平行市场世界不是泛化叙事，而是预测市场原生模拟：每个世界都必须回答事件如何穿过市场网络、改变哪些 odds、制造哪些 edge、触发哪些风险，并留下怎样的可验证记录。

该引擎把智能体讨论结果压缩成结构化交易智能对象：scenario tree、affected markets、probability shift、AI fair odds、edgeNet、risk flags、suggested size、Arc proof hash 和 track record entry。

13 / 用户工作流与产品体验

用户工作流与产品体验

用户连接钱包，选择 root outcome，系统召回候选市场并生成 AI 推理图，用户审查 causal script，进入订单预览，确认 dry-run 或真实 CLOB 签名，并可将 trace 锚定到 Arc。

14 / 风控、治理与合规边界

风控、治理与合规边界

系统默认不托管私钥、不保证收益、不绕过用户确认。自动化执行必须以显式授权、明确预算、范围限制、紧急停止和可撤销机制实现。

18 / 护城河、指标与结论

护城河、指标与结论

Causeway 的护城河来自市场结构理解、推理数据闭环、Arc 可验证历史、x402 智能体服务层、群体智能预测能力和用户治理边界。
